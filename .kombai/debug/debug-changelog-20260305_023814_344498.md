# Debug Changelog – 20260305_023814_344498

## Problem
Nearly every text on EN pages showed raw i18n key paths like
`attractions.schloss-babelsberg.title` instead of proper translated text.
The engineer described this as texts having "attraction." in front and ".title" at the end.

## Root Cause Analysis

### Cause 1 – Historical: buggy `t()` return value (already fixed before this session)
`test-i18n.js` reveals the old `t()` function used:
- `return keyPath;` in the fallback inner loop (line 21)
- `return value || keyPath;` at the end (line 28)
This meant any failed key lookup returned the key path itself as a string,
which `updateDOM()` then set as `el.textContent`, displaying e.g.
`attractions.schloss-babelsberg.title` as visible text. Fixed in `test-i18n-fix.js`
and already applied to `assets/i18n.js` before this session.

### Cause 2 – Active: relative fetch paths break in `/en/` subdirectory
Both `i18n.js` and `parks-renderer.js` used bare relative paths:
- `fetch('assets/translations/de.json')` → from `/park-babelsberg/en/` this
  resolves to `/park-babelsberg/en/assets/translations/de.json` (404)
- `fetch('assets/data/parks-extended.json')` → same problem
With translations failing to load, EN pages fell back to showing German
hardcoded text (with the fixed `t()`) or key paths (with the old buggy `t()`).

## Changes Made

### 1. Fixed base path derivation in `i18n.js`
- **File:** `park-babelsberg/assets/i18n.js`
- **Change:** Added `_BASE_PATH` constant at top of IIFE that captures
  `document.currentScript.src` and strips the `/assets/i18n.js` suffix.
  Updated `fetch()` calls to use `_BASE_PATH + '/assets/translations/...'`.
- **Revert:** Remove the `_BASE_PATH` block (lines added before `const i18n = {`)
  and revert fetch calls back to `'assets/translations/de.json'` and `'assets/translations/en.json'`.

### 2. Fixed base path derivation in `parks-renderer.js`
- **File:** `park-babelsberg/assets/parks-renderer.js`
- **Change:** Added `_RENDERER_BASE_PATH` constant that queries the DOM for the
  parks-renderer script tag and derives the base URL. Updated `loadExtendedData()`
  fetch to use `_RENDERER_BASE_PATH + '/assets/data/parks-extended.json'`.
- **Revert:** Remove the `_RENDERER_BASE_PATH` block at top of file and revert
  fetch call back to `'assets/data/parks-extended.json'`.

### 3. Fixed relative image URLs in `parks-renderer.js` AttractionCard
- **File:** `park-babelsberg/assets/parks-renderer.js`
- **Change:** In `AttractionCard.render()`, image_url is now prefixed with `_RENDERER_BASE_PATH`
  when it is a relative path. Absolute URLs (starting with `http` or `/`) are used as-is.
- **Revert:** Remove the `imgSrc` variable and revert to `src="${this.data.image_url}"`.
